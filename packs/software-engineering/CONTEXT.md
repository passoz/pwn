# AI Engineering Skills Domain Model

The reusable language and constraints that govern the installed engineering skills without imposing a technology stack or coupling the process to Pi.

## Language

**Existing Project Convention**:
The documented local instructions, automation and established repository patterns that govern work in an existing project. It takes precedence over global engineering preferences unless the user explicitly requests a migration.
_Avoid_: global default stack, inferred preferred framework

**Documentation Requirement**:
An obligation to update an existing project document when a change affects an external contract or operational procedure. If no trustworthy destination exists, the agent asks the user instead of creating a documentation structure by assumption.
_Avoid_: optional docs task, guessed docs folder

**Behavior Change**:
A change to externally observable software behavior. It follows RED → GREEN → REFACTOR when the project has a test harness; RED must fail for the new behavior rather than an incidental environment failure.
_Avoid_: incidental failure, untested behavior change

**Behavior-Preserving Refactor**:
An internal change that does not alter observable behavior. It requires the relevant existing regression check but does not require a new RED test.
_Avoid_: behavior change disguised as refactor

**Test Harness Absence**:
A condition established only after checking local instructions, project scripts, CI, manifests/test files and README for an executable test path. It permits an explicit limitation report, not an invented test framework.
_Avoid_: assumed absence, skipping discovery

**Security Gate**:
A project-configured SAST, dependency scan or secret scan discovered through local instructions, scripts, CI or documentation. It is blocking when configured; when none exists, the outcome is explicitly `N/A` and the agent does not install or invent a tool.
_Avoid_: assumed scanner, optional configured security check

**Operational Safety Rule**:
A non-negotiable constraint against exposing secrets or executing dangerous commands such as privilege escalation, shell-piped downloads, destructive resets, unapproved installation, deployment or publication. An exact product-dependency installation recorded in the task plan and mechanically matched to the governing Spec is approved by that contract; it never authorizes privilege escalation, global installation or additional packages.
_Avoid_: convenience exception, silent dangerous command, package inferred from implementation

**Spec-Declared Dependency Installation**:
An exact package-manager command recorded under `Dependency installations` in a task plan whose named packages appear in the governing Spec's structured `Dependencies`/`Dependências` declaration. It is a recoverable environment prerequisite, not a terminal decision; absence from the plan or Spec remains an unapproved installation and blocks execution.
_Avoid_: blanket package-manager permission, substring-only user assumption, undeclared transitive tool

**Dangerous-Action Authorization**:
A single-session approval for a concrete, necessary group of dangerous commands, including their targets and effects. The agent asks only when those actions are required, groups them into one confirmation, and does not treat generic approval as authorization.
_Avoid_: blanket approval, cross-session approval, per-step confirmation

**Decision Escalation**:
The narrow set of cases that require a user question: ambiguous product or contract requirement, hard-to-reverse architecture, necessary dangerous action, genuinely indeterminate stack/command/document destination after discovery, or conflict between local instructions and the user request. Facts discoverable in the repository and reversible low-risk decisions do not require escalation.
_Avoid_: precautionary interruption, invented decision

**Application-Generated Persistent Identifier**:
The identifier assigned by the application to a newly created persistent entity. The global default is UUID v7 generated by the backend/server, except where an existing project or external integration requires a different identifier.
_Avoid_: client-generated UUID, unplanned ID migration

**Relational Data Access Policy**:
For new relational persistence, prefer explicit SQL and versioned migrations; do not introduce an ORM without an explicit user request or established local convention. Existing ORM-based projects retain their convention and are never migrated automatically.
_Avoid_: unrequested ORM, automatic ORM removal

**Versioned Migration**:
An ordered, reviewable schema transition for persistent relational data. New relational stores require versioned migrations; existing stores retain their established migration mechanism; non-relational storage does not imply migrations.
_Avoid_: ad hoc production schema edit, migration requirement for cache/filesystem

**External Boundary**:
The separation between business rules and transport, persistence or external providers. Introduce a port/interface only when an external dependency, multiple implementation, useful isolated test or real coupling risk justifies it; do not create layers for a single simple implementation.
_Avoid_: interface-for-everything, forced Clean Architecture layout

**Public HTTP API**:
An HTTP interface consumed outside its implementation boundary. New public APIs use explicit versioning unless the project has an established alternative; error format and middleware follow local convention.
_Avoid_: unversioned new public API, globally imposed route prefix

**Long-Running HTTP Service**:
A service that remains available to serve HTTP requests. It handles termination signals gracefully and exposes liveness/readiness when dependency availability matters; these requirements do not apply to CLIs, libraries, static frontends or one-off jobs.
_Avoid_: health endpoint for every executable, forced middleware order

**Localized UI Text**:
Text presented to an application user when the product supports localization. It belongs in the project's established locale mechanism rather than backend implementation code; projects without localization retain their existing editorial pattern unless the user requests i18n.
_Avoid_: backend UI string, forced i18n migration

**Container Build**:
A containerized build is permitted when it is organized and well constructed. The selected build strategy follows the project and its reproducibility, security and delivery needs; compilation inside Docker is not globally prohibited.
_Avoid_: blanket host-only build rule, disorganized container build

**Container Build Baseline**:
For new or changed container builds, use an appropriate `.dockerignore`, preserve dependency cache opportunities where practical, avoid build tooling in the runtime image when naturally separable, run non-root where possible, keep secrets out of images, and provide testable build/runtime commands. Multi-stage builds and service count remain contextual decisions.
_Avoid_: mandatory multi-stage build, fixed service-count rule

**Target Platform Validation**:
Build and test the actual target platform. Cross-compilation and multiple release artifacts are required only when product requirements, CI or the release process explicitly require them.
_Avoid_: mandatory cross-compilation, untested target platform

**Operational Logging**:
Structured operational records of events, errors and correlation context using the project’s established logger or the native ecosystem default for a new service. Sensitive values are never logged; request bodies and headers require sanitization and a diagnostic need.
_Avoid_: forced logging library, raw sensitive request logging

**Project Quality Gate**:
The relevant automated validation configured by a project’s CI or local workflow. Existing gates must pass for a completed change; platform, linter, hook and pipeline structure follow the project rather than a global prescription.
_Avoid_: fixed CI platform, globally imposed lint tool

**Work ID**:
A four-digit, repository-local, monotonically increasing identifier shared by one source snapshot, validated change prompt, task plan and namespaced execution evidence. `.work/NNNN.json` reserves the ID before other artifacts exist; removed or abandoned IDs are never reused.
_Avoid_: global counter, latest-plan inference, reused gap, untracked numeric filename

**Work Manifest**:
The versioned `.work/NNNN.json` index that records a Work ID's origin, canonical artifact paths and lifecycle state. It is portable project state, not task completion evidence, and divergence between it and named artifacts is blocking.
_Avoid_: Meridian-only mapping, database-only reservation, silently repaired mismatch

**Numbered Work Artifacts**:
A work uses `.sources/NNNN-*.md` for its immutable input snapshot, `.prompts/NNNN-change.md` for the WHAT/WHY delta, `.todo/NNNN-tasks.md` for the authoritative task markers, and Work-ID subdirectories for evidence, diagnostics, screenshots and acceptance candidates.
_Avoid_: arbitrary output path, newest prompt selection, shared evidence namespace

**Local Task Plan**:
The local `.todo/NNNN-tasks.md` file is the planning and execution state for one Work managed through the engineering workflow skill. Execution requires an explicit Work target. The agent does not query remote issues; external orchestrators may create source snapshots before invoking the suite.
_Avoid_: remote issue synchronization by the suite, implicit `.todo/tasks.md`, automatic latest plan

**Qualified Task Dependency**:
A dependency on another plan in the same repository, written as `NNNN/task-id` in the authoritative task plan. The repository-wide graph validator checks existence and cycles; cross-repository dependencies are not part of this contract.
_Avoid_: database-only dependency, cross-repository implicit edge

**Acceptance Candidate**:
A deterministic, unsigned summary generated after independent acceptance audit. It binds Work ID, task ID, plan hash, audited implementation/test snapshots and evidence digest. It remains independently verifiable but is not a trust signature; an external supervisor may observe and sign it without giving signing keys to the agent.
_Avoid_: agent-authored pass claim, external private key in workspace, signed-by-suite fiction

**Artifact Contract Version**:
The format version declared by a workflow artifact, independent from the product/content version recorded by a system specification. New task plans use the current contract; legacy plans remain executable when they contain every fact required for safe execution, and compatibility warnings do not masquerade as blocking failures.
_Avoid_: treating content version as format version, silently applying current rules to an unversioned artifact

**Workflow Contract Compatibility**:
Contract evolution is additive whenever possible. A breaking contract release must preserve safety checks, identify legacy artifacts deterministically, provide an idempotent previewable migration in the same release, and keep the immediately previous executable contract readable during the compatibility window. Migration never invents project facts or runs automatically during task execution. When a mechanical limit cannot be repaired without changing scope, migration may preserve the exact observed legacy value with explicit provenance; the exception is rejected if invented, broadened or stale.
_Avoid_: all-or-nothing validation of legacy plans, silent migration, unbounded grandfathering, weakening safety for compatibility
